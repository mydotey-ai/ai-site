# 架构总览

## 系统架构

AI-Site 采用前后端分离架构，前端和后端独立开发、独立部署。

```
┌─────────────────────────────────────────────────────────────────┐
│                           用户浏览器                              │
└─────────────────────────────────────────────────────────────────┘
                    │                           │
                    ▼                           ▼
        ┌─────────────────────┐     ┌─────────────────────┐
        │   Site (用户网站)    │     │  Admin (管理后台)    │
        │   Vue 3 + Vite      │     │   Vue 3 + Vite      │
        └──────────┬──────────┘     └──────────┬──────────┘
                   │                           │
                   └───────────┬───────────────┘
                               │
                               ▼
                    ┌─────────────────────┐
                    │      Nginx          │
                    │   (反向代理/静态)    │
                    └──────────┬──────────┘
                               │
              ┌────────────────┼────────────────┐
              │                │                │
              ▼                ▼                ▼
    ┌──────────────┐  ┌──────────────┐  ┌──────────────┐
    │  API 服务     │  │ Admin 服务   │  │  静态资源     │
    │ Spring Boot  │  │ Spring Boot  │  │   (CDN)      │
    └──────┬───────┘  └──────┬───────┘  └──────────────┘
           │                 │
           └────────┬────────┘
                    │
                    ▼
         ┌─────────────────────┐
         │      MySQL/SQLite    │
         └─────────────────────┘
```

## 模块划分

### 前端模块

| 模块 | 技术栈 | 说明 |
|------|--------|------|
| admin | Vue 3 + Naive UI | 管理后台，内容管理 |
| site | Vue 3 + 自定义 UI | 用户网站，内容展示 |
| shared | TypeScript | 共享组件和工具 |

### 后端模块

| 模块 | 说明 | 依赖 |
|------|------|------|
| common | 公共代码、配置、工具 | 无 |
| api | 对外 API 服务 | common |
| admin | 管理后台服务 | common |

## 设计原则

### 架构原则

1. **关注点分离**: 前后端分离，模块职责清晰
2. **领域驱动**: 按业务领域组织代码
3. **单一职责**: 每个模块/类职责单一
4. **开闭原则**: 对扩展开放，对修改关闭

### 开发原则

1. **代码规范**: 遵循编码规范，保持代码一致性
2. **测试驱动**: 核心逻辑需要单元测试覆盖
3. **文档先行**: 重要设计需要文档记录
4. **安全优先**: 重视安全性，防止常见攻击
