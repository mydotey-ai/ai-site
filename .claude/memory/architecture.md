# 架构决策记录

## ADR 概述

本文档记录项目中的重要架构决策及其背景、影响。

---

## ADR-001: 前后端分离 + Monorepo 架构

**状态**: 已采纳

**背景**:
- 项目需要支持多种前端展示形态（管理后台 + 用户网站）
- 后端需要提供多入口服务（API服务 + 管理服务）
- 需要统一管理代码版本和依赖

**决策**:
- 采用前后端分离架构
- 使用 Monorepo 单仓库管理所有代码
- 前端分为 admin（管理后台）和 site（用户网站）两个独立项目
- 后端分为 common（公共）、api（对外服务）、admin（管理服务）三个模块

**影响**:
- 优点：代码统一管理，依赖版本一致，便于重构
- 缺点：仓库体积较大，需要使用 pnpm workspace 管理依赖

## ADR-002: 后端 DDD 四层架构

**状态**: 已采纳

**背景**:
- 业务领域清晰（博客、作品集、创作、多媒体）
- 需要良好的代码组织和可维护性
- 支持未来的业务扩展

**决策**:
采用 DDD 四层架构：
1. **接入层 (controller/dto)**: HTTP接口、参数校验、DTO转换
2. **应用服务层 (command/query/job)**: 用例编排、事务管理
3. **领域层 (entity/repository/enums)**: 领域对象、业务规则
4. **基础设施层 (infrastructure)**: 持久化、外部服务

**影响**:
- 优点：职责清晰，易于测试，支持 CQRS
- 缺点：初期开发需要更多抽象

## ADR-003: 数据库双支持 (MySQL + SQLite)

**状态**: 已采纳

**背景**:
- 生产环境需要稳定的关系型数据库
- 开发/演示环境需要轻量化部署
- 个人项目需要灵活的部署选项

**决策**:
- 生产环境使用 MySQL
- 开发/轻量部署使用 SQLite
- 使用 Flyway 管理数据库迁移
- MyBatis Plus 提供数据库兼容性

**影响**:
- 需要维护两套数据库迁移脚本
- 需要注意 SQL 语法的兼容性
- 增加了部署灵活性

## ADR-004: 前端双项目架构

**状态**: 已采纳

**背景**:
- 管理后台和用户网站的功能和 UI 完全不同
- 两者的访问模式和性能要求不同
- 需要独立部署和迭代

**决策**:
- admin 项目：管理后台，使用 Naive UI
- site 项目：用户网站，自定义设计
- shared 项目：共享组件和工具

**影响**:
- 优点：职责分离，独立部署，按需加载
- 缺点：需要维护两套前端代码

## ADR-005: JDK 25 + Spring Boot 3.5

**状态**: 已采纳

**背景**:
- 项目需要使用最新的 Java 特性
- Spring Boot 3.5 支持最新 JDK
- 追求更好的性能和开发体验

**决策**:
- JDK 版本：25
- Spring Boot 版本：3.5.x
- MyBatis Plus：最新稳定版

**影响**:
- 需要使用支持 JDK 25 的开发环境
- 可使用最新的 Java 语言特性（虚拟线程、模式匹配等）
