# 全局开发规则

## 核心原则

- 遵循 SOLID 原则，保持代码简洁、可读
- 编写可测试的代码，避免过度设计
- 所有用户输入必须验证，敏感信息不得提交代码库
- 合理使用缓存，优化关键路径

---

## Code Review 清单

- [ ] 代码是否符合规范
- [ ] 是否有安全风险
- [ ] 是否有性能问题
- [ ] 测试是否充分
- [ ] 文档是否更新

---

## 测试原则

- 单元测试覆盖核心逻辑
- 集成测试覆盖关键流程
- E2E 测试覆盖用户场景

---

## Phase/Plan 完成流程

当一个 Phase 完成时，**必须**检查和更新相关文档：

1. **更新 Phase 文档** (`/docs/plans/phases/phase-X-xxx.md`)
2. **更新计划总览** (`/docs/plans/README.md`)
3. **同步更新相关文档**

   参考 `/docs/README.md` 更新所有相关文档，新文档按目录规范创建。
